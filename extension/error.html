Start the backend server

The extension talks to a local backend running at http://127.0.0.1:8000. It isn't running right now, so nothing happens when you try to simplify a page.

  1. Open a terminal and go to the backend/ folder of the project.
  2. First time only — set up the environment: 
    python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
  3. Start the server: 
    ./run_dev.sh
    (or directly: uvicorn main:app --reload --port 8000)
  4. Come back to this tab — it will update automatically once the backend is reachable.

Wait for the model to finish loading

The backend is running, but it hasn't finished loading the simplification model yet (this can take a little while on first start, especially the first time it downloads a model). Keep this tab open — it will update automatically once loading finishes.

If it's been stuck for a long time, check the terminal running the backend for errors, e.g. a missing or misconfigured model. There's no live download-progress percentage available yet — the elapsed timer above is the only signal this page can show right now.

This model isn't configured on the backend

The backend finished starting up, but the model you've selected isn't one of the ones it actually loaded — this won't resolve itself by waiting, unlike a model that's still loading.

To make it available instead, set that model's env var and restart the backend. Each key has one, named after it — SIMPLIFIER_MODEL_ONLINE, SIMPLIFIER_MODEL_FINETUNED, SIMPLIFIER_MODEL_DOCUMENT, SIMPLIFIER_MODEL_LLM_7B, and so on. The backend's startup log names every key it skipped and the variable that would enable it.

For the prompted-LLM keys (llm_…) the usual cause is the Ollama sidecar: it has to be running before the backend starts, with the tag already pulled. ./run_dev.sh starts it for you; otherwise run ollama serve and ollama pull <tag>, then restart the backend.

The backend didn't respond correctly

The backend is up and reports its model as loaded, but a test request failed or returned no usable text. Check the terminal running the backend for errors.

Open a regular webpage

Browser pages like chrome://, about:, the new-tab page, and local file:// pages can't run extensions at all — that's a restriction the browser enforces, not something this extension can change.

Open a normal website (http:// or https://) and click the toolbar icon there instead.

If you specifically need this on a local file:// page, go to chrome://extensions, find this extension, and enable "Allow access to file URLs".

Refresh the tab you're trying to use

The tab you clicked the icon on was already open before the extension was installed, reloaded, or updated, so it doesn't have the extension's script loaded yet.

Refresh that tab (or close and reopen it), then click the toolbar icon again.

Start the demo server

The demo pages (demo/) are served separately, by the same script that runs the backend.

  1. Open a terminal and go to the backend/ folder of the project.
  2. Start it: 
    ./run_dev.sh
  3. Open the demo page again from the toolbar icon's right-click menu.

Serves on port 8001 by default. If you started it with a custom DEMO_PORT, update DEMO_ORIGIN in extension/background.js to match.
